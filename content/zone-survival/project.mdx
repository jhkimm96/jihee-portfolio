## 프로젝트 개요

3분 동안 살아남는 웹 게임입니다. 지도 밖으로 안전 구역이 줄어들고(자기장), 플레이어 주변에 폭격이 떨어지고, 추적자가 쫓아옵니다. 아이템 3종(회복, 가속, 보호)이 있고, 폭격을 추적자에게 맞추면 추적자를 쓰러뜨릴 수 있습니다.

게임 자체보다 **규칙을 정하고, 기록으로 확인하고, 고친 과정**을 보여주는 것이 목적입니다. 모든 수정은 `docs/balance-log.md`에 "수정 전 / 수정 후 / 이유 / 바꾼 뒤 결과" 형식으로 남겼습니다.

![시작 화면 — 규칙과 아이템 설명, 닉네임 입력](/zone-survival/images/start.png)

## 내가 맡은 범위

개인 프로젝트이고 구현은 Claude Code와 함께 진행했습니다. 규칙과 수치의 방향을 정하고, 플레이 소감과 시뮬레이션 결과로 수정 방향을 고르고, 계획서를 승인하는 일은 직접 했습니다.

- 규칙 설계: 자기장 단계와 피해, 폭격, 추적자, 아이템 3종
- 검증 도구: 시드 고정 시뮬레이션, 봇 시뮬레이션(`docs/balance/bot-sim.mjs`), 자동 테스트
- 기록 체계: 판별 로그, Supabase 저장, 리포트
- 절차: 코드 계획서 승인 → 테스트 먼저 → 구현, 푸시하면 테스트와 배포가 자동으로 실행

## 규칙과 화면

200×200m 지도를 걷고, 화면은 캐릭터를 따라 움직이며, 우측 상단 미니맵에 안전 구역과 아이템, 위협이 보입니다.

![플레이 화면 — 폭격 예고 원과 안전 구역 예고선](/zone-survival/images/warning.png)

![후반 화면 — 폭격 5개, 추적자, 아이템, 효과 남은 시간](/zone-survival/images/late.png)

위 두 장은 시드를 고정한 시뮬레이션으로 재현한 장면이고, 체력과 효과 시간은 캡처용 값입니다.

![결과 화면 — 종료 원인과 기록 저장 상태](/zone-survival/images/result.png)

결과 화면의 숫자는 화면 구성을 보여주려고 넣은 예시 값입니다.

## 수정 이력

| 버전 | 바꾼 것 | 이유 |
|---|---|---|
| v0.1 | 9×9 격자, 중앙 시작, 자기장 3단계 | 첫 규칙 세트 |
| v0.2 | 최종 구역에서 가장 먼 모서리에서 시작 | 가만히 있어도 클리어되던 허점 |
| v0.3 | 200m 연속 지도, 원형 자기장, 장애물, 미니맵 | 격자는 이동 압박이 거의 없었음 |
| v0.4 | 폭격과 추적자, 안내 표시 | 자기장만으로는 예고를 보고 이동하면 모두 클리어 |
| v0.5 | 폭격이 추적자도 맞춤, 한 줄 의견 저장 | 추적자를 죽일 방법이 없다는 소감 |
| v0.6 | 추적자 생성 12초, 동시 6마리 | 추적자를 죽일 수 있어 쉽다는 소감 |
| v0.7 | 판마다 무작위 시드 | 같은 첫 판 지도를 외워 쉬워질 수 있음 |

각 수정의 근거와 봇 결과는 [저장소의 balance-log](https://github.com/jhkimm96/zone-survival/blob/main/docs/balance-log.md)에서 볼 수 있습니다.

## 기록과 분석 흐름

판이 끝나면 한 줄이 Supabase에 저장됩니다. 저장되는 것은 버전, 시드, 닉네임과 익명 ID, 클리어 여부, 생존 시간, 사망 단계와 원인, 원인별 피해, 아이템, 기기이고, 실명이나 연락처는 받지 않습니다. 리포트는 모든 비율에 분모를 쓰고, 판 수가 30 미만이면 해석을 [추정]으로 표시합니다.

## 한계와 현재 상태

- 사람 플레이 기록은 수집 중입니다. 목표 클리어율(약 15~20%)은 가설이고, 사람 난이도는 [미확인]입니다.
- 봇은 규칙의 허점을 찾는 용도이고 사람의 난이도를 대표하지 않습니다. 예를 들어 v0.5에서 폭격으로 추적자를 쓰러뜨릴 수 있게 했을 때 봇의 클리어율은 오히려 낮아졌습니다.
- 지금까지 난이도에 대한 사람의 의견은 개발자 본인 한 명의 플레이 소감뿐입니다.
- 상용 게임이나 팀 개발 경험이 아니라, 한 개의 규칙 세트를 만든 개인 프로젝트입니다.
