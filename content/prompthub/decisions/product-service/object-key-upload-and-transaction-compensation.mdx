## 문제

FE가 만료되는 presigned URL을 미리보기와 상품 저장에 함께 사용했다. 서버는 URL에서 S3 키를 다시 추출해야 했고, URL 형식이 바뀌면 저장 로직도 영향을 받았다. DB 저장이 실패해도 이미 S3에 복사한 영구 파일은 자동으로 되돌아가지 않는 문제도 있었다.

## 결정

- `previewUrl`은 화면 미리보기에만 사용한다.
- `objectKey`는 상품 저장·수정·업로드 취소에 사용한다.
- 서버는 임시 키의 형식과 판매자 ID, thumbnail·image·file 용도를 검증한다.
- 상품 유형별 필드를 파일 복사 전에 검증한다.
- DB commit 후 임시 파일을 삭제한다.
- DB rollback 시 새 영구 복사본만 삭제하고, 재시도를 위해 임시 파일은 유지한다.

<details>
<summary><b>파일 승격과 보상이란?</b></summary>

파일 승격은 아직 상품에 확정되지 않은 임시 파일을 상품의 영구 경로로 복사하는 과정이다. S3에는 파일 이동 명령이 없어 실제로는 복사 후 원본을 삭제한다.

S3 작업은 DB rollback으로 취소되지 않는다. 따라서 상품 저장이 실패하면 애플리케이션이 이번 시도에서 만든 영구 복사본을 직접 삭제한다. 이런 반대 작업을 보상이라고 한다.

</details>

## 선택 이유

URL을 계속 저장하면 클라이언트와 서버가 S3 주소 형식에 종속된다. 반대로 objectKey를 계약으로 사용하면 서버가 저장 대상을 직접 검증할 수 있고, 미리보기 주소가 만료돼도 상품 데이터에는 영향이 없다.

임시 파일을 먼저 삭제하지 않고 commit까지 유지하는 이유는 저장 실패 후에도 사용자가 같은 파일로 재시도할 수 있게 하기 위해서다.

## 결과

만료 URL이 상품 데이터에 저장되지 않고, 다른 판매자나 다른 용도의 키를 상품에 연결하는 요청을 차단했다. 파일 일부만 복사된 상태에서 실패하면 이미 만든 복사본을 정리하고, DB 저장 실패 후 영구 경로에 불필요한 파일이 남는 위험도 줄였다.

기존의 presigned PUT 결정은 유지한다. 기존 글이 파일 바이트를 product-service가 중계하지 않는 이유를 설명한다면, 이번 결정은 업로드 이후 FE·BE 저장 계약과 실패 복구 방식을 보완한다.

## 남은 범위

DB commit 후 임시 파일 삭제만 실패하면 상품과 영구 파일은 정상이지만 임시 객체가 남을 수 있다. 실제 잔존 문제가 관측되면 임시 경로의 수명주기 정리를 운영 안전망으로 추가한다.
