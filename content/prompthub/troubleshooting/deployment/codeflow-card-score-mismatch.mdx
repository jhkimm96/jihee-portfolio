## 문제

웹 CodeFlow 분석기에서는 `A / 92점`이 표시됐지만, GitHub README 카드와 카드 JSON에는 계속 `C / 72점`이 표시됐다.

처음에는 카드 파일이 갱신되지 않는 문제로 보였지만, 카드 워크플로는 실행되고 있었고 분석 로그도 남고 있었다.

<details>
<summary><b>🔍 카드와 웹 분석기는 원래 같은 도구 아닌가?</b></summary>

CodeFlow 카드와 웹 분석기는 같은 분석 로직을 사용할 수 있지만, 카드 액션은 실행 시점에 액션 패키지 안에 포함된 분석기 버전을 사용한다.

웹 서비스가 최신 코드로 업데이트되어도 GitHub Actions가 오래된 커밋이나 태그를 사용하면 두 결과가 달라질 수 있다.

</details>

## 원인

GitHub Actions는 다음 액션을 사용하고 있었다.

```yaml
braedonsaunders/codeflow/card@v1
```

공식 저장소의 `v1` 태그는 최신 분석기를 자동으로 따라가는 태그가 아니었다. 실제 실행 로그에서 `v1`이 2026-07-06 커밋을 내려받는 것을 확인했다.

반면 웹 CodeFlow는 이후 수정된 최신 분석기를 사용하고 있었다. 그래서 같은 저장소를 분석해도 웹과 GitHub 카드의 결과가 달랐다.

<details>
<summary><b>🔍 태그가 v1 하나뿐이면 업데이트가 없는 것 아닌가?</b></summary>

태그의 개수와 코드 업데이트 여부는 별개다.

CodeFlow 저장소에는 `v1` 태그만 있었지만, 그 이후에도 `main` 브랜치의 분석기 코드는 업데이트되고 있었다. 다만 `v1` 태그가 최신 커밋으로 이동하지 않아 `@v1` 사용자는 이전 분석기를 계속 받게 됐다.

</details>

또한 PR #727에서 데이터베이스 비밀번호 기본값 fallback을 제거하는 보안 수정이 develop에 반영된 상태였다. 따라서 최신 점수는 다음 두 변화가 함께 반영된 결과였다.

- PR #727의 실제 보안 수정
- 최신 CodeFlow 분석기로 재분석

<details>
<summary><b>🔍 72점에서 92점이 된 것이 코드 품질 20점 개선이라는 뜻인가?</b></summary>

그렇게 단정할 수 없다.

PR #727은 실제 보안 문제를 수정했지만, PR #728은 서비스 코드를 추가로 고친 PR이 아니다. 이번 점수 차이에는 PR #727의 수정과 분석기 버전 변경이 함께 영향을 줬다.

따라서 `72 → 92`는 “이번에 코드 품질이 한 번에 20점 좋아졌다”가 아니라, 수정된 현재 코드 상태를 최신 분석 기준으로 다시 측정한 결과로 기록해야 한다.

</details>

## 해결

공식 저장소에 `v2`나 `v4` 태그는 없었기 때문에 존재하지 않는 버전명을 사용하지 않았다.

대신 검증한 최신 커밋 SHA를 CodeFlow 액션에 직접 고정했다.

```yaml
braedonsaunders/codeflow/card@e9bfb8c3855d37dfae6e9a8e8aab3b99682dd0cc
```

이후 워크플로를 수동 실행하고 카드 파일이 실제로 갱신되는지 확인했다.

## 결과

최신 분석기 실행 결과는 다음과 같았다.

```text
files=1855
functions=2531
loc=208307
grade=A
score=92
```

`.github/codeflow-card.json`과 `.github/codeflow-card.svg`에 새 결과가 반영됐다.

기존 `C / 72점`은 이전 분석기의 실행 기록으로 남기고, 최신 분석기 결과부터 새로운 품질 추세의 기준으로 사용한다.

<details>
<summary><b>🔍 카드 갱신 PR과 CodeFlow Receipt은 어떻게 다른가?</b></summary>

카드 갱신 PR은 현재 저장소 전체 상태를 README 카드에 반영하기 위한 유지보수 PR이다.

CodeFlow Receipt은 특정 PR을 검토하거나 머지할 당시의 LOC, 함수 수, blast radius, health 등을 남기는 리뷰 기록이다.

따라서 과거 Receipt을 최신 분석기로 다시 계산해 바꾸지 않는다. 과거 기록은 당시의 분석 기준을 보존하고, 이후 카드와 Receipt부터 최신 분석기를 사용한다.

</details>

## 배운 점

- GitHub Action의 태그가 하나뿐이라고 분석기 코드가 업데이트되지 않는 것은 아니다.
- 태그가 최신 커밋을 가리키는지 실제 실행 로그와 커밋 SHA로 확인해야 한다.
- 카드 점수는 현재 저장소 전체 상태이고, Receipt은 특정 PR 당시의 리뷰 기록이다.
- 점수 변화가 코드 개선 때문인지 분석기 기준 변경 때문인지 분리해서 기록해야 한다.
