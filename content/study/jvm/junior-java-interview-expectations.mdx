## 결론

초급자에게 모든 Java API나 고급 시스템 설계를 기대하지 않는다. 대신 기본 문법과 OOP를 사용해 작은 문제를 풀고, 선택 이유와 실패 가능성을 설명할 수 있기를 기대한다.

```mermaid
flowchart LR
  A[정의 암기] --> B[작은 코드 작성]
  B --> C[선택 이유 설명]
  C --> D[실패·trade-off 설명]
```

| 영역 | 기대 수준 |
|---|---|
| OOP | 네 원칙을 말하고 인터페이스·상속 선택을 설명한다 |
| 컬렉션 | List·Set·Map 선택과 equals/hashCode 관계를 안다 |
| 예외 | 원인을 숨기지 않고 적절한 계층에서 처리한다 |
| 동시성 | 공유 상태와 중복 처리 위험을 인식한다 |
| Spring | DI와 요청 흐름을 따라갈 수 있다 |
| 테스트 | 단위·통합 테스트의 목적을 구분한다 |
| SQL/HTTP | 기본 조회·갱신과 REST 의미를 설명한다 |

<details>
<summary><b>면접에서 좋은 답변의 형태</b></summary>

정의만 말하지 말고 “이 코드에서는 무엇을 선택했고, 다른 선택은 어떤 비용이 있으며, 실패하면 어떻게 확인할지”까지 연결한다. 모르는 것은 추측하지 않고 확인 방법을 말하는 편이 낫다.
