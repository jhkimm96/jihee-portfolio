## 01 · 새 앱을 켰다고 예전 파일까지 따라오지는 않는다

상품 앱 A의 컨테이너 내부 쓰기 공간에 파일을 넣었다. A를 새 컨테이너 B로 바꾸면 그 공간이 이어진다고 기대하면 안 된다.

```text
컨테이너 내부에만 저장  A의 파일 → B에는 없음
별도 볼륨에 저장       A ─┐
                         공용으로 이어 쓸 저장공간
                      B ─┘
```

**교체해도 필요한 데이터와 환경 설정은 실행 이미지의 수명과 분리한다.** 그렇다고 모든 볼륨이 영구적이거나 동시에 여러 앱에서 쓰기 가능한 것은 아니다.

## 02 · 저장공간과 신청서는 다른 물건이다

PV는 Kubernetes가 관리하는 저장공간 자원, PVC는 앱이 그 공간을 요청하는 객체다.

```text
Pod → PVC “필요한 저장공간 신청” → PV “연결할 저장공간”
```

Pod 삭제와 디스크 삭제는 같은 작업이 아니다. 어떤 볼륨인지, PVC 삭제 시 회수 정책은 무엇인지까지 본다. Retain은 자동 회수를 막는 정책이지 백업이 아니다. 노드에 붙은 local 볼륨은 노드 장애 시 다른 노드로 디스크가 자동 복제되지 않는다. [Persistent Volume](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)

## 03 · 같은 이미지로 설정만 바꿔 실행한다

| 실행 밖에서 넣을 값 | 기본 선택 |
| --- | --- |
| 공개 가능한 기능 설정 | ConfigMap |
| 비밀번호나 인증 토큰 | Secret |

PromptHub 상품 Deployment는 비밀번호 값을 직접 적는 대신 `secretKeyRef`로 Secret의 특정 키를 참조한다.

```text
이미지 [앱 코드] + 실행 환경 [Secret에서 읽은 값] → 실행 앱
```

**Secret의 base64 표현은 암호화가 아니다.** 접근 권한과 저장 시 암호화, 로그 유출 방지와 키 교체가 필요하다. 참조 파일에 값이 안 보이는 것만으로 저장소 전체가 안전하다고 판단하지 않는다. [Secret 보호 조건](https://kubernetes.io/docs/concepts/configuration/secret/)

## 04 · 설정을 바꾸면 이미 켜진 앱도 바로 바뀔까?

```text
환경 변수로 시작: 앱 A가 값1을 읽음
ConfigMap 변경: 값2 저장
계속 실행 중인 A: 환경 변수는 여전히 값1
새 Pod로 교체: 값2로 시작
```

ConfigMap 환경 변수는 자동 갱신되지 않는다. 볼륨 파일 주입은 방식에 따라 나중에 갱신될 수 있지만 앱이 파일을 다시 읽는지도 별개다. [ConfigMap 갱신](https://kubernetes.io/docs/concepts/configuration/configmap/)

<details>
<summary>값을 공개하지 않고 참조만 읽기</summary>

```yaml
env:
  - name: POSTGRES_PASSWORD
    valueFrom:
      secretKeyRef:
        name: postgres-secret
        key: PRODUCT_SERVICE_PASSWORD
```

현재 상품 Deployment의 참조 발췌다. 실제 Secret 값은 열거나 복사하지 않았다. Secret·ConfigMap·PV·PVC는 Kubernetes 기본 객체이며 Java 라이브러리를 설치하는 개념이 아니다.

</details>

## 프로젝트 근거와 확인 범위

2026-10-09 `k8s/base/services/product/deployment.yaml`의 Secret 참조를 읽었다. 실제 값 관리 위치, 클러스터 암호화·권한·데이터 보존·복구는 검증하지 않았다. 위 저장공간 장면은 원리 설명이지 디스크 장애 실험 결과가 아니다.
