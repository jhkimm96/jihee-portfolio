## 01 · 연결 한 자리를 A가 빌렸다

DB 연결은 DB와 대화할 때 빌리는 통로다. 설명을 위해 연결이 하나뿐이라고 하자. A가 상품을 읽은 뒤 외부 API를 기다리는 동안 B도 상품을 읽으려 한다.

```text
반납한 경우
A: [DB 조회·반납] [외부 API 기다림........]
B:               [같은 연결 빌려 DB 조회]

계속 점유한 경우
A: [DB 조회]     [연결 가진 채 외부 API 대기] [반납]
B:               [연결 자리 기다림........] [DB 조회]
```

결과: DB 계산이 느리지 않아도 연결을 못 빌려서 요청이 느려질 수 있다. 위 시간과 연결 개수는 독립 설명 예제다.

## 02 · OSIV는 작업 공간을 오래 열어 둔다

**OSIV(open-in-view)**는 요청 처리 동안 JPA의 작업 공간인 EntityManager를 유지하는 방식이다. 서비스 트랜잭션이 끝난 뒤에도 화면에서 연관 데이터를 로딩할 수 있게 한다. [Spring OSIV API](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/orm/jpa/support/OpenEntityManagerInViewFilter.html)

```text
요청:          [조회 처리][외부 API 대기][응답]
EntityManager: [────열려 있을 수 있음────]
트랜잭션:      메서드 경계와 전파 설정으로 확인
DB 연결:       실제 획득·반납 시각으로 확인
```

결과: 작업 공간이 열렸다는 사실만으로 DB 통로도 계속 점유한다고 단정할 수 없다. Hibernate의 연결 획득·반납 모드와 트랜잭션 경계가 영향을 준다. [Hibernate connection handling](https://docs.hibernate.org/orm/current/userguide/html_single/#transactions-connection-handling)

## 03 · 스위치를 바꾸기 전에 점유부터 확인한다

1. 외부 호출 구간에 트랜잭션이 열려 있는지 본다.
2. 연결 획득부터 반납까지가 그 대기 구간을 포함하는지 본다.
3. 연결 점유 시간과 풀 대기 요청 수를 함께 본다.

느린 외부 호출을 DB 트랜잭션 밖으로 분리할지, 화면에 필요한 값을 서비스에서 미리 준비하고 OSIV를 끌지 선택한다. OSIV를 꺼도 외부 호출까지 감싼 긴 트랜잭션은 남을 수 있다.

더 자세한 진단: [DB가 느릴 때 병목은 어떻게 확인하나](/study/cs/database-bottleneck-diagnosis).

<details>
<summary>설정과 코드 예제는 어떻게 읽나?</summary>

`spring.jpa.open-in-view`는 Spring Boot의 JPA 웹 설정이다. OSIV는 트랜잭션 자체를 요청 전체로 늘리는 설정이 아니다. 트랜잭션은 실제 annotation, 프록시 호출과 전파 설정을 확인한다.

다음은 흐름을 보여주는 발췌형 의사 코드다. 생략된 의존성·타입·save 정의가 있어 그대로 실행하는 전체 구현이 아니다.

```java
@Service
public class PrepService {
    public Result create(Request req) {
        var tags = tagRepository.findAll();
        var result = externalApiClient.call(req);
        return save(result);
    }
}
```

`@Service`는 Spring annotation, 저장소와 externalApiClient는 애플리케이션이 연결하는 코드다. DB 조회 → 외부 응답 대기 → 저장 순서만 보여준다. 이 발췌만으로 각 구간의 최종 트랜잭션 경계를 확정할 수 없다.

OSIV를 끄면 응답 직렬화나 화면 처리에서 뒤늦게 연관 데이터를 읽는 경로를 점검해야 한다. 필요한 값을 미리 준비하지 않으면 LazyInitializationException이 발생할 수 있다.

</details>

<details>
<summary>프로젝트의 현재 설정이라고 단정해도 될까?</summary>

2026-10-08에 읽은 로컬 PromptHub의 여러 서비스 설정에는 open-in-view:false가 있다. 실제 활성 profile과 배포된 최종 설정, 연결 점유 실측은 확인하지 않았다. 과거 OSIV 위험과 현재 배포 상태를 동일시하지 않는다.

</details>
