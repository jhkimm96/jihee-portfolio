## 01 · 많은 기록 중 주문 7만 찾고 싶다

여러 앱의 기록이 쌓여 있다. 주문 7의 결제가 시간 초과된 시각은 10월 8일 오전 10시 5분이다. 다음은 시간 필드를 추가한 학습용 기록이다. 실제 고객의 주문이나 운영 로그가 아니다.

```json
{"@timestamp":"2026-10-08T10:05:00+09:00","event":"payment_timeout","orderId":7,"durationMs":3000}
```

**어느 데이터에서, 언제의 기록을, 어떤 조건으로 찾는지** 세 가지를 고른다. 이 글은 Kibana의 기록 탐색 화면인 **Discover**에서 Data View를 사용하는 흐름이다. 로그가 저장소에 먼저 저장되어 있어야 한다.

## 02 · 검색 범위와 시간을 먼저 고른다

**Data View**는 Kibana에서 검색할 데이터 범위와 필드를 보는 설정이다. 여기서는 `app-logs-*`라는 학습용 범위로 `app-logs-2026.10.08` 등의 이름을 가진 저장 데이터를 고른다. `*`는 뒤가 달라도 포함한다는 뜻이다. 기록을 복사해 새로 저장하는 기능은 아니다. [Data View 만들기](https://www.elastic.co/docs/explore-analyze/find-and-organize/data-views/create-data-view)

아래는 **실제 Kibana 화면 캡처가 아닌 이해용 화면 스케치**다.

```text
┌ 주문 오류 찾아보기 ────────────────────────┐
│ 데이터: app-logs-*                        │
│ 시간: 10/8 10:00 ~ 10:10 (한국 시간)        │
│ 조건: 결제 시간 초과 + 주문 번호 7          │
├──────────────────────────────────────────┤
│ 10:05  주문 7  payment_timeout  3000ms     │
└──────────────────────────────────────────┘
```

이 범위와 시간 안에서 주문 7의 오류를 찾는다. 시간 기준은 `@timestamp`다. 이 필드가 날짜 타입으로 저장되어 있고 화면의 시간대가 한국 시간이라는 조건이다. 지금 시각 기준 '최근 15분'을 고르면 과거 10시 5분 기록은 안 보일 수 있다.

## 03 · 사건과 주문 번호를 조건으로 넣는다

위 스케치의 조건은 “결제 시간 초과이고 주문 번호가 7인 기록”이다. 같은 데이터라도 이 조건을 넣으면 다른 주문의 오류는 제외된다.

<details>
<summary>검색창에 실제로 쓰는 조건은?</summary>

**KQL**은 Kibana 검색창에서 조건을 적는 문법이다. Java 코드나 별도 설치 라이브러리가 아니다. 예제에서는 `event`가 사건 이름을 검색할 수 있는 필드, `orderId`가 숫자 필드라는 전제다.

```text
event: "payment_timeout" and orderId: 7
```

입력하면 선택한 데이터와 시간 범위 안에서 두 조건을 함께 만족하는 기록을 찾는다. 프로젝트에서 필드를 다른 이름이나 구조로 저장했다면 조건도 바꿔야 한다.

Kibana의 ES|QL 방식은 Data View 없이 조회할 수도 있다. 이 글은 모든 검색 방식을 설명하지 않는다. [Discover 사용하기](https://www.elastic.co/docs/explore-analyze/discover/discover-get-started)

</details>

## 04 · 저장하는 것은 기록이 아니라 보는 방법이다

```text
오늘: 데이터 범위 + 검색 조건 + 표시할 열을 정함 → 검색 화면 저장
다음: 저장한 검색 화면을 엶 → 그때의 시간 조건으로 데이터를 다시 조회
```

**Saved Object**는 Data View, 검색 화면, 대시보드처럼 다시 사용할 설정을 저장한 객체다. Data View도 Saved Object의 한 종류다. 시간 범위를 함께 저장했는지에 따라 다음에 조회할 범위가 달라질 수 있다.

**설정을 내보낸 파일은 원본 로그 데이터의 백업이 아니다.** 저장한 화면을 다시 열어도 주문 7의 원본 데이터가 없으면 그 기록은 나오지 않는다. [Saved Objects](https://www.elastic.co/docs/explore-analyze/find-and-organize/saved-objects)

## 프로젝트에서는 어디를 확인했나?

2026-10-08 로컬 PromptHub에서 Gateway 로그 범위와 `@timestamp`를 지정한 Data View 파일, 그 파일을 Kibana에 가져오도록 작성된 설정을 확인했다. 가져오기 성공이나 실제 검색 결과까지 확인한 것은 아니다. 원격 저장소와 배포 상태도 확인 범위 밖이다.

프로젝트의 실제 범위 이름과 이 글의 `app-logs-*` 예시는 구분한다. 실제 Kibana 메뉴 위치와 화면 모양도 버전에 따라 달라질 수 있다.
