## 01 · 상품 7 캐시는 60초만 두기로 했다

Redis는 키와 값을 저장하는 외부 서버다. TTL(Time To Live)은 키가 남아 있을 유효기간이다. 별도 Java 기본 클래스의 이름이 아니다.

```text
0초   product:7 생성 / 유효기간 60초
30초  아직 조회 가능
60초  만료 → 조회하면 없는 키로 취급
```

**시간이 끝나는 것과 공간이 부족해 먼저 버리는 것은 다른 사건이다.** 아래 장면은 예시이며 프로젝트의 실제 TTL 설정이 아니다.

## 02 · 60초가 지나기 전에 너무 많이 들어오면?

서로 다른 새 키가 초당 1,000개씩 들어와 각각 60초 남는 단순 모델을 생각해보자.

```text
1초 뒤   약 1,000개
30초 뒤  약 30,000개
60초 뒤  유효한 키만도 약 60,000개 규모
```

TTL은 입력량을 제한하지 않는다. 키·값 크기와 부가 비용, 실제 만료 제거 속도에 따라 메모리는 달라진다. 만료된 키는 접근 시와 주기 검사로 제거되므로 정각에 모든 물리 메모리가 한꺼번에 반환되는 그림으로 이해하지 않는다. [Redis 만료 처리](https://redis.io/docs/latest/commands/expire/)

## 03 · 공간이 모자란 순간의 선택은 별도다

`maxmemory`는 Redis의 메모리 관리 한도, `maxmemory-policy`는 그 한도에서 제거할 기준이다.

```text
한도 도달
  noeviction  → 기존 키를 축출하지 않음 → 새 데이터를 늘리는 명령 거절 가능
  allkeys-lru → 표본에서 덜 최근에 쓴 키 축출 → 새 데이터 공간 마련
```

순수 읽기 명령은 noeviction 한도에서도 동작할 수 있다. “모든 쓰기 명령이 반드시 실패한다”로 외우지 않는다. LRU는 최근 사용 기준이며 Redis의 LRU는 근사 방식이다. [Redis 축출 정책](https://redis.io/docs/latest/develop/reference/eviction/)

## 04 · product:7과 lock:7을 같은 식으로 버려도 될까?

| 보관 대상 | 먼저 제거되면 생기는 일 |
| --- | --- |
| 다시 만들 수 있는 상품 캐시 | DB 재조회 증가 |
| 로그인 세션 | 인증 흐름 변화 |
| 잠금·작업 상태 | 중복 실행이나 처리 유실 위험 |

캐시를 살리려 선택한 축출 정책이 중요한 상태까지 없앨 수 있다. 정책의 적용 범위와 데이터의 복구 방법부터 확인한다. TTL이 있는 키만 고르는 volatile 정책도 후보가 없으면 공간을 만들지 못할 수 있다.

## 05 · 컨테이너 256Mi와 Redis 한도는 같은 설정이 아니다

현재 PromptHub Redis StatefulSet은 이미지 태그 `redis:7.4-alpine`, 컨테이너 메모리 한도 256Mi와 AOF 옵션을 선언한다. **읽은 매니페스트에는 maxmemory와 축출 정책을 명시하지 않았다.** 실제 서버 설정은 아직 확인하지 않았다.

```text
Redis 내부 공간 관리 → maxmemory와 정책
컨테이너 전체 상한    → 256Mi
                        서로 자동으로 같은 값이 되지는 않음
```

내부 정책이 동작하기 전에 컨테이너 전체가 OOM 종료될 수도 있다. 버퍼 등 전체 사용과 Redis 한도를 함께 보고 여유를 정한다. 이미지 태그는 실행 버전의 실측이나 최신 안정 버전 확인이 아니다.

<details>
<summary>진단할 값은 어디서 읽을까?</summary>

Redis의 `INFO memory`, `INFO stats`와 실제 설정에서 used_memory, maxmemory, evicted_keys, expired_keys 및 거절된 명령 변화를 확인한다. 누적 수치는 시간 구간의 증가량으로 비교한다.

축출이 늘어 DB 조회까지 급증하면 [캐시 동시 재조회](/study/cs/cache-stampede-and-single-flight)로 이어 본다. 이번에는 Redis 명령을 실제 서버에 실행하지 않았다.

</details>
