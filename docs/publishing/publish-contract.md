# 공통 게시 계약

이 문서는 `publish`, `publish-study`, `publish-troubleshooting`, `publish-decision`,
`publish-reviews`, `publish-quality`가 공통으로 따른다. 기록 유형별 스킬의 더 엄격한 공개 제한은
이 문서보다 우선한다.

## 게시 범위 승인

파일을 쓰기 전에 사용자에게 다음을 보여주고 승인을 받는다.

- 게시 또는 수정할 파일
- 글마다 답할 핵심 질문 또는 기록할 사실
- 핵심 주장과 근거 범위
- Learning Path, 기존 글, 프로젝트 문서처럼 함께 수정할 파일

한 번의 승인은 표에 적힌 파일과 주장 범위 전체에 적용된다. 같은 범위의 파일마다 같은 내용
승인을 반복하지 않는다. 다음 경우에만 다시 확인한다.

- 파일 수, 핵심 주장, 삭제 범위가 바뀐다.
- 기존 URL이나 공개 결론을 바꿔야 한다.
- slug 충돌, 근거 충돌 또는 범위 밖 연결이 발견된다.
- 민감정보를 일반화하면 사실관계나 기여 범위가 달라진다.

## 공개 근거 조사

현재 프로젝트의 코드, 설정, 테스트, 이슈와 PR을 대조해 실제 사용 여부와 기여 범위를 확인한다.
대화 요약이나 과거 문서만으로 현행 상태를 단정하지 않는다.

외부 자료를 사용할 때는 출처의 역할을 구분한다.

- 일반 검색, 공개 블로그, 영상과 SNS는 사례와 설명 관점을 찾는 데 사용한다.
- 공식 문서, 명세, 릴리스 노트, 공식 구현 소스는 기술적 사실과 지원 상태를 확인하는 기준으로
  사용한다.
- 프로젝트 코드는 포트폴리오에서 실제 사용한 사실의 기준으로 사용한다.

블로그나 SNS의 주장을 검증 없이 기술적 사실로 쓰지 않는다. 출처 문장, 이미지와 구성을 복제하지
않고 새 예시와 표현으로 작성한다.

## 민감정보 자동 검사

사용자에게 `없음` 확인을 요구하지 않는다. 초안 승인을 받은 뒤 다음 범위를 자동 검사한다.

- 게시할 초안과 생성·수정할 콘텐츠 파일
- 이번 게시와 관련된 Git diff
- 글에서 직접 인용한 코드, 설정과 문서

검사 대상은 비공개 조직·고객 이름, 내부 도메인과 URL, Secret·자격증명·토큰, 팀원 실명,
미공개 사업 정보, 내부 식별자와 접근 경로다.

1. 후보가 없으면 `민감정보 자동 점검: 통과`로 기록하고 진행한다.
2. 명백한 후보는 일반화하거나 제외한 뒤 다시 검사한다.
3. 일반화가 글의 사실관계나 기여 범위를 바꾸는 애매한 후보만 사용자에게 질문한다.
4. Secret, 미조치 취약점의 재현 절차 등 고위험 후보는 원문을 출력하지 않는다. 파일 위치와
   유형만 마스킹해 알리고, 안전한 공개 범위가 정해질 때까지 게시하지 않는다.

저장소 전체를 무차별 검사하지 않는다. 현재 게시와 직접 연결된 파일만 검사한다.

## 읽기 쉬운 공개 기록

한 절은 주장 하나만 다룬다. 같은 내용을 문단, 표, 그림과 결론에서 반복하지 않는다. 근거와
결론을 멀리 떨어뜨리지 않고, 처음 나오는 필수 용어는 본문에서 쉽게 설명한다. 더 깊은 배경과
구현 변형처럼 없어도 흐름을 따라갈 수 있는 내용만 토글로 보충한다.

## 검증과 결과 보고

기록 유형의 스키마, 링크, slug, 관련 콘텐츠와 빌드 규칙을 확인한다. 기존 dirty worktree의
unrelated 파일은 포함하지 않는다. 사용자가 이번 요청에서 명시하지 않은 push는 하지 않는다.

결과에는 변경 파일, 근거 조사 범위, 민감정보 자동 검사 결과, 검증 결과와 커밋 해시를 남긴다.
