# 12시간 플랜

사용자가 대화에서 제시한 작은 확장 설계(전용 URL, 개념·기출·원문 연결, 개별 채점, 기존 오답 저장, 돌아오기)를 승인했다.

1. 파일: 위 목록. 데이터와 화면을 나누고 기존 허브·저장 코드만 연결한다.
2. 흐름: URL의 cram 구간 선택 → 개념 또는 지정 문제 → recordCramAnswer → 기존 오답/백업. 빈 답은 기록하지 않는다. 전체 모의고사와 별개로 개별 풀이 기록을 남긴다.
3. 재사용: gradeAnswer, recordProgrammingAttempt의 기록 구조, WrongAnswerNotebook, createBackup/restoreBackup. 기존 10일 진도와 모의고사 답안은 변경하지 않는다. 기존 programmingAttempts 배열은 이미 공통 문항 ID로 오답 표시가 가능하다.
4. 최소 구현: 새 서버·계정·DB·자동 시간 만료·새 저장 스키마 제외. 구간 위치는 URL, 제출 기록은 기존 저장소.
5. 가독성: cramBlocks는 학습 내용, CramPlanPanel은 선택과 표시, recordCramAnswer는 개별 제출 정책. 기존 모의고사와 구분되는 이름 사용.
6. 루브릭 예측:
   - controller-thin: 괜찮음, UI는 저장 함수에 위임.
   - entity-encapsulation: 괜찮음, 순수 진행 상태 갱신 재사용.
   - http-semantics: 해당 없음, API 없음.
   - logging-quality: 해당 없음, 서버 로그 없음.
   - exception-discipline: 괜찮음, 기존 저장 오류 처리 유지.
   - layer-separation: 괜찮음, 문제 데이터와 기록 로직 분리.
   - dead-code: 괜찮음, 실제 메뉴 연결만 추가.
   - duplication-semantic: 위험, 새 채점기를 만들지 않고 기존 함수 재사용.
   - diagnosability: 괜찮음, 미제출과 제출 결과 구별.
   - integration-robustness: 해당 없음, 외부 API 없음.
   - service-boundary: 해당 없음, 서비스 없음.
   - value-object-design: 괜찮음, 구간은 명명된 데이터 객체.
   - polymorphism-opportunity: 해당 없음, 확장 계층 불필요.
   - cohesion-coupling: 위험, 기존 허브에 세부 UI를 더하지 않고 패널 분리.
7. 테스트 먼저: 720분 합계, 모든 참조 ID 유효, 진단/학습에서 최종 회차 제외, 빈 답 무기록, 오답 한 문제만 저장, 정답·재풀이·백업 보존, 서브넷 채점. 이후 타입 검사·빌드 및 URL/화면 확인.
